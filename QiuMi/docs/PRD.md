# 嫂子模拟器 · 产品需求文档

## 一、产品概述

### 1.1 产品定位
一款以"内娱时代峰峻男爱豆秘密女友"为核心体验的沉浸式文字模拟游戏。玩家扮演一位与养成系偶像维持秘密恋情的女性，在聚光灯照不到的角落体验浪漫、压力、抉择与冒险。

### 1.2 目标用户
- 对养成系偶像文化有了解的女性用户
- 喜欢互动小说、文字冒险类游戏的玩家
- 对内娱饭圈生态感兴趣的群体

### 1.3 核心体验
- 真实还原手机操作体验（微博、微信、抖音等12个应用）
- 回合制剧情推进，每次选择影响关系走向
- 隐藏属性逐步揭露，营造悬疑感
- 开放式结局，至少50回合的游戏深度

## 三、核心系统详述

### 3.1 回合系统

每回合由三个阶段组成：

**阶段一：信息同步**
- 自动生成微博热搜推送（60%概率）
- 自动生成男友微信消息（40%概率）
- 自动生成其他微信通知（25%概率）
- 自动生成骚扰/陌生短信（20%概率）
- 自动生成未接来电（15%概率）

**阶段二：自由行动**
- 玩家拥有3个行动点
- 可选行动：查看手机、处理工作、休息、逛街、运动、学习、探班、约朋友
- 选择"查看手机"后进入手机桌面，可依次打开各应用
- 所有行动点耗尽或玩家主动结束后进入下一阶段

**阶段三：随机事件**
- 每4回合触发约会事件
- 每3回合触发生活事件
- 每5回合触发事业事件
- 每7回合触发娱乐圈大事件
- 每8回合有60%概率触发危机事件
- 事件逐个推进，每个事件提供ABCD选项
- 所有事件处理完毕后进入下一回合

### 3.2 手机模拟系统

模拟一部真实手机的完整交互体验：

| 应用 | 模拟内容 | 数据来源 |
|------|---------|---------|
| 微博 | 热搜榜单、推荐帖子、点赞评论数 | 模板库随机抽取 |
| 微信 | 聊天列表、对话界面、消息气泡 | 模板库 + 男友名称动态注入 |
| T-FAMILY | 官方公告、成员动态、社区帖子 | 模板库 + 团体名称动态注入 |
| B站 | 视频推荐列表、播放量 | 模板库随机抽取 |
| 抖音 | 短视频信息流、点赞数 | 模板库随机抽取 |
| 小红书 | 双列笔记流、标签 | 模板库随机抽取 |
| QQ | 群聊列表、好友列表 | 静态模板 |
| 网易云音乐 | 歌单推荐、好友动态 | 静态模板 |
| 短信 | 短信列表 | 模板库 + 系统自动推送 |
| 电话 | 通话记录 | 系统自动生成 |
| 相册 | 照片网格、私密相册 | 静态展示 |
| 设置 | 存档导出/导入 | 游戏引擎交互 |

### 3.3 角色系统

**玩家身份（8种）**：粉丝、经纪人、演员/歌手同行、练习生、造型师、素人、制作人、财阀背景

每种身份影响：
- 前置剧情中的相遇方式
- 初始叙事风格

**男友角色（22位）**：
- TFBOYS：王俊凯、王源、易烊千玺
- TNT时代少年团：马嘉祺、丁程鑫、宋亚轩、刘耀文、张真源、严浩翔、贺峻霖
- TOP登陆少年组合：朱志鑫、张泽禹、张极、左航、苏新皓
- TF-ing厂牌：穆祉丞、邓佳鑫、童禹坤、张子墨、黄朔
- Solo艺人：张峻豪、余宇涵

每位男友包含：真实姓名、常用昵称、性格描述、所属团体、队内担当

**隐藏属性（8种，随机分配）**：
海王、渣男、回避型、事业狂魔、中央空调、双性恋、妈宝男、控制狂

**感情基础（6种，随机分配）**：
真心相爱、各取所需、利益交换、欺骗、寂寞消遣、疗伤替代品

**保密原因（8种，随机分配）**：
养成系恋爱禁止条款、公司强烈反对、事业上升期、害怕伤害粉丝、团体发展考虑、关系不稳定、家人反对、合约禁止

### 3.4 怀孕系统

**触发条件**：每4回合提供一次亲密机会

**概率计算**：
- 采取安全措施：1%意外怀孕概率
- 不采取安全措施：40%怀孕概率

**后续流程**：
1. 身体出现异常症状（恶心、停经等）
2. 玩家选择购买验孕棒或忽略
3. 验孕结果：90%准确率（10%假阳性）
4. 玩家选择告知男友或隐瞒
5. 医院确认（100%准确）
6. 去留决策（最终决定权在玩家）

### 3.5 关系系统

**核心数值**（不显示给玩家，仅通过事件描写体现）：
- 好感度：0-100，影响求婚条件
- 信任度：0-100，影响出轨概率
- 出轨风险：累积值，达到阈值触发出轨事件

**关系状态流转**：
恋爱中 → 分手 → 复合 → 订婚 → 结婚（隐婚）→ 离婚

**关键节点**：
- 30回合后可触发求婚
- 好感度≥70时满足求婚条件
- 结婚后触发隐婚相关事件链

### 3.6 存档系统

- 导出格式：JSON文本
- 包含内容：游戏进度、玩家数据、男友数据、手机消息、怀孕状态、关系状态
- 操作入口：设置应用内
- 版本校验：存档携带版本号，不兼容时拒绝读取

## 四、事件系统

### 4.1 事件分类

| 类别 | 内容方向 | 触发频率 |
|------|---------|---------|
| 约会事件 | 车内秘密约会、家中相聚、国外旅行 | 每4回合 |
| 事业事件 | 回归期、绯闻风波、获奖 | 每5回合 |
| 危机事件 | 私生饭跟踪、公司施压 | 每8回合（60%概率） |
| 生活事件 | 闺蜜聚会、工作机遇 | 每3回合 |
| 娱乐圈事件 | 颁奖典礼、同行恋情曝光 | 每7回合 |

### 4.2 事件结构

每个事件包含：
- 唯一标识
- 标题（含emoji）
- 叙事文本（小说式描写，每行不超过30字）
- 四个选项（A/B/C/D），每个选项仅描述玩家的行动或对话，不包含任何提示或预告

## 五、技术方案

| 层面 | 选型 | 说明 |
|------|------|------|
| 前端框架 | Vue 3 + Vite | 响应式UI，组件化开发 |
| 状态管理 | Pinia | 四个独立Store管理游戏/玩家/男友/手机状态 |
| 路由 | Vue Router | Hash模式，三个页面 |
| 游戏引擎 | 自建事件驱动状态机 | 纯JavaScript类，与UI完全解耦 |
| 数据存储 | JSON文件导出/导入 | 存档以文本形式复制粘贴 |
| 样式方案 | Scoped CSS | 组件级样式隔离 |
